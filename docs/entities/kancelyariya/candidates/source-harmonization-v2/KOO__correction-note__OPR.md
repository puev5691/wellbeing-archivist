# КООРДИНАТОР: поправки к пакету гармонизации источников

## Смысл

Независимая проверка пакета КАНЦЕЛЯРА подтвердила основную диагностику и выявила несколько швов, которые необходимо учитывать до утверждения кандидатов.

## Уже исправлено в GitHub

- `project-instructions-core-v2-candidate.md`: четыре класса источников вместо трёх; короткая схема маршрутизации применяется только при утверждённом и подключённом routing-каноне.
- `engineering-task-filter-v1-candidate.md`: исправлена логически неудачная формула «одновременно выполняется хотя бы одно условие».
- `KAN__project-chat-instructions-v2-candidate__OPR.md`: отдельно указаны техническое состояние загрузки инструкции и нормативный статус кандидата.
- контрольные суммы соответствующих GitHub-пакетов пересчитаны после изменений.

## Исправлено в передаваемой локальной редакции, но ещё не заменено в GitHub

`file-work-canon-universal-v2_2-candidate.md`:

1. контрольная сумма в `manifest` требуется только когда для пакета предусмотрена проверка целостности;
2. `upload-task` создаётся только когда доставка требует отдельного отслеживаемого шага; если файл уже фактически доставлен или отдельная задача доставки не нужна, `upload-task` не создаётся.

Причина незавершённой GitHub-замены: доступный интерфейс GitHub заменяет файл только полным телом; для этого крупного файла нет безопасного частичного patch-действия. Исправленная полная версия приложена к пакету КООРДИНАТОРА для ручной замены ОПЕРАТОРОМ.

## Поправка к карте замены recovery

В `KAN__source-corpus-audit__OPR.md` строка карты замены должна различать три объекта:

- действующий источник: `SHT__entity-state-preservation-and-recovery-canon__OPR(1).md`;
- промежуточный кандидат v1.1: provenance/черновой этап, не текущий канон;
- предлагаемый кандидат: `entity-state-preservation-and-recovery-canon-v1_2-candidate.md`.

Нельзя трактовать промежуточный v1.1-кандидат как действующий источник.

## Recovery v1.2

Переданная ранее в чат КООРДИНАТОРА копия v1.2 была устаревшей только в служебной карточке. В исправленном пакете используется версия с SHA-256:

`9956f57dd0e7be3c5a6380596d1c0249fb1f1c4dffd3bfd745be2de76b121176`

Она совпадает с текущей GitHub-версией кандидата.

## Что остаётся решением ОПЕРАТОРА

КООРДИНАТОР не присваивает кандидатам статус `approved`.

После технических поправок остаётся отдельное решение ОПЕРАТОРА:

- какие кандидаты утвердить и сделать активными источниками;
- утверждать ли верхнюю инструкцию v2 как нормативный источник, а не только технически загруженный текст;
- принимать ли понятийное ядро v0.2, которое затрагивает содержательную модель проекта.
